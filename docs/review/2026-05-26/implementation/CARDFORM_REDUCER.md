# CardFormDialog — useReducer + unique field ids

Closes the `card-form-dialog.tsx` slice of P2 #12. Consolidates the
component's seven independent `useState`/`useRef` calls into a single
`useReducer`, and replaces hard-coded element ids with `useId()` so the
"lint disabled in line 1 with `<explanation>` placeholder" goes away.

## File-size delta

|                                                | Before | After |
|------------------------------------------------|-------:|------:|
| `card-form-dialog.tsx`                         | 389    | 412   |
| `card-form-state.ts` (new)                     | —      | 147   |

The dialog itself grew slightly because `dispatch({ type: ..., ... })`
calls are longer than `setX(...)` calls. The win is *not* fewer lines
overall — it's that all state transitions are now in **one place**
(`cardFormReducer`), and the component is straight JSX + effects + event
plumbing. Reading the reducer top-to-bottom you can see every rule that
governs the form, including the auto-derive pinyin behavior.

## State before / after

**Before** (`useState` x4 + `useState`+`useRef` mirror + 2 effects):

```ts
const [values, setValues] = useState<CardEditorValues>(...);
const [pending, setPending] = useState(false);
const [converting, setConverting] = useState(false);
const [questionManuallyEdited, setQuestionManuallyEdited] = useState(false);
const [error, setError] = useState<string | null>(null);
const questionManuallyEditedRef = useRef(questionManuallyEdited);

useEffect(() => {                       // mirror state -> ref
  questionManuallyEditedRef.current = questionManuallyEdited;
}, [questionManuallyEdited]);
```

The `ref` existed because the auto-fill `setTimeout` callback ran 350ms
after the user's last keystroke and needed to re-check "did the user
type into the question field in the meantime?" *without* a stale
closure. Manual ref mirroring of state is a code smell.

**After** — one reducer:

```ts
type CardFormState = {
  values: CardEditorValues;
  pending: boolean;
  converting: boolean;
  error: string | null;
  questionManuallyEdited: boolean;
};

type CardFormAction =
  | { type: "reset"; values: CardEditorValues }
  | { type: "setQuestion"; text; source: "manual" | "auto"; isPinyinHanziPack }
  | { type: "setAnswer"; text }
  | { type: "setQuestionImage"; image }
  | { type: "setQuestionAudio"; audio }
  | { type: "setError"; error }
  | { type: "submitStart" } | { type: "submitFinish"; error? }
  | { type: "convertStart" } | { type: "convertFinish"; pinyin?; error? }
  | { type: "autoFillQuestion"; hanzi; pinyin };
```

The `autoFillQuestion` action is the key insight: instead of the
`setTimeout` callback closing over a ref to re-check user state, it
just dispatches an action with the `hanzi` value it was scheduled for.
The reducer checks current state and refuses to apply if the user has
since edited the question, the answer has changed, or the question is
non-empty. The 350ms debounce still lives in the component as a
`setTimeout` (with a `cancelled` flag in cleanup), but the staleness
check is now declarative and inside the reducer.

`assertNever(action)` in the default branch gives an exhaustive
discriminated-union check.

## How `useUniqueElementIds` was resolved

The original file had:

```ts
/** biome-ignore-all lint/correctness/useUniqueElementIds: <explanation> */
```

…with the literal string `<explanation>` left as the placeholder. Two
problems:

1. The project doesn't even use Biome — it uses ESLint
   (`client/eslint.config.js`). The comment was inert. Probably copy-pasted
   from a template or generated by a tool run that never landed.
2. The reason the rule *would* have failed: `card-form-dialog.tsx`
   hard-coded ids like `id="card-question"` and `id="card-answer"`. On
   `pack-cards-page.tsx` the **same component is mounted twice** at the
   same time (create + edit dialog). When both opened (e.g. user opens
   create while edit is still mounted), the DOM had duplicate `id`
   attributes — a real a11y/label-targeting bug.

Fix: `const reactId = useId();` then `id={`card-question-${reactId}`}`
etc. Each dialog instance now gets unique ids. The biome-ignore line is
deleted.

## Sub-components extracted

None. I considered extracting `<PinyinFields>` / `<StandardFields>`
and a `useCardImageUpload` hook, but:

- The image/audio upload code is ~25 lines each — extracting a hook would
  add indirection without making any reader's job easier.
- The pinyin vs standard branch differs only in the field ordering
  (answer-before-question vs question-before-answer) and the
  "Convert from hanzi" button. Splitting would duplicate the textarea
  markup or require a 4-prop wrapper.

The reducer extraction alone hits the actual goals (one state surface,
explicit transitions, no manual ref mirroring).

## Manual verification checklist

These can't be unit-tested cheaply; spot-check before shipping:

- [ ] Basic pack: create new card, fill question + answer, submit → card
      appears in list
- [ ] Basic pack: edit existing card, change text, save → row updates
- [ ] Image-recall pack: create card with image upload, preview shows,
      remove-image button clears it, submit succeeds
- [ ] Image-recall pack: validation fires when both image and text are
      empty
- [ ] Pinyin-hanzi pack: type hanzi in answer field → after 350ms, pinyin
      auto-fills in question field
- [ ] Pinyin-hanzi pack: type in question field manually → from then on,
      changing the answer does NOT overwrite the question
- [ ] Pinyin-hanzi pack: click "Convert from hanzi" button → pinyin fills
      even if question was previously manually edited (the button is an
      explicit user action)
- [ ] Pinyin-hanzi pack: re-open the create dialog (close + open) → the
      manual-edit flag resets, auto-fill works again
- [ ] Open create dialog AND edit dialog simultaneously → DevTools shows
      no duplicate `id="card-question-*"` attributes; clicking labels
      focuses the correct field in the correct dialog
- [ ] Cancel button on a pending submit → no orphan state on next open
- [ ] Error display: trigger a submit error → red alert visible, then
      typing in any field clears it
